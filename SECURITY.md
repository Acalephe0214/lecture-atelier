# Security policy

This is a local personal-workflow prototype, not a security-audited service. Keep it on loopback. Do not add public hosting, multi-user access or network exposure without a separate security design.

Do not disclose real credentials, recordings, private paths or source transcripts in public issues. If you suspect a leak, stop further sharing, revoke affected credentials through the provider, and check repository history and any published archives. Deleting a current file alone does not remove it from existing commits or copies.

A dedicated private vulnerability-reporting channel is not currently available. Public bug reports should use synthetic examples and exclude sensitive exploit details or private data.

No model or dependency is downloaded merely by opening the app. First-run installation is separate and asks for download consent. Preserve upstream licenses and verify the origin of packages, models and binaries.
